# Experimental setup

The pilot experiments use the first 10,000 records of the Clothing, Shoes and Jewelry metadata file, not the full category of about 7.2 million products. Task A uses the 4,602 listings with a composition string, restricted to the 9 materials with at least 20 labeled listings in the pilot (this cutoff was computed on all labeled pilot rows); Task B uses all 10,000 listings, since every product has an average rating. The same scripts will rerun unchanged on a 50,000-product and a 250,000-product sample, drawn by hashing each product's identifier with a fixed seed, and the final tables will come from those runs.

Each listing is assigned once to the training set (80%) or the test set (20%) with NumPy's random generator seeded at 42, and both tasks use that same assignment. This gives 3,641 training and 903 test listings for Task A, and 8,046 training and 1,954 test listings for Task B. All models are fitted on the training set only, including the TF-IDF vocabulary, the imputation medians, and the one-hot categories, and each model is scored once on the test set. We did not use cross-validation or tune hyperparameters on the pilot; every setting listed in the method section was fixed in advance, and tuning with five-fold cross-validation on the training part of the 50,000-product sample is the next step.

Two leakage rules shape the inputs. For Task A, any clause containing a percentage is removed from the text before training, and a self-check (`python analysis/load_data.py`) fails if any labeled listing still contains one. For Task B, no feature comes from the product's own ratings or reviews; the rating count enters only as a sample weight. Task A is scored by macro-F1, $\frac{1}{K}\sum_k 2P_kR_k/(P_k+R_k)$, so that every material counts equally, and Task B by $\text{RMSE} = \sqrt{\frac{1}{n}\sum_i (y_i - \hat{y}_i)^2}$ and $\text{MAE} = \frac{1}{n}\sum_i \lvert y_i - \hat{y}_i\rvert$ on the unweighted test set.

The setup can be reproduced from the public repository with `python analysis/material_tfidf.py` and `python analysis/rating.py`; each run took under 30 seconds on a laptop CPU (12-thread Intel), using scikit-learn 1.9.1, XGBoost 3.4.1, and pandas 3.0.6, and writes the command, seed, and data version next to every metric. The data loading and split are in the cell "Load the data" of [`analysis/load_data.py`](https://github.com/johnha912/amazon-clothing-material/blob/main/analysis/load_data.py), the Task A setup in the cells "Prepare Task A" and "Train both TF-IDF models" of [`analysis/material_tfidf.py`](https://github.com/johnha912/amazon-clothing-material/blob/main/analysis/material_tfidf.py), and the Task B setup in the cells "Features from listing fields only" and "Train the three models" of [`analysis/rating.py`](https://github.com/johnha912/amazon-clothing-material/blob/main/analysis/rating.py).
