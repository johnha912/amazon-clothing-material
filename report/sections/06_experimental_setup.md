# Experimental setup

The experiments use the ~250,000-product sample of the Clothing, Shoes and Jewelry metadata file (data version `data/sample.parquet (249,762 rows, make_sample.py 2219c1e)`, seed 42), not the full category of about 7.2 million products. Task A uses the 90,979 listings with a composition string, restricted to the classes with at least 20 labeled listings (`MIN_CLASS_ROWS = 20`; all ten classes of the shared `src/labels.py` pass, so no row is dropped); Task B uses all 249,762 listings, since every product has an average rating. An earlier pilot on the first 10,000 records of the file validated the pipeline, and its numbers appear in this report only where labeled as pilot.

Each listing is assigned once to the training set or the test set by `src/make_sample.py`, which hashes the product identifier with seed 42 and sends about 20% of products to the test set; both tasks use that same assignment. This gives 72,661 training and 18,318 test listings for Task A, and 199,838 training and 49,924 test listings for Task B. All models are fitted on the training set only, including the TF-IDF vocabulary, the imputation medians, and the one-hot categories, and each model is scored once on the test set. We did not use cross-validation or tune hyperparameters; every setting listed in the method section was fixed in advance, and five-fold cross-validated tuning remains future work.

Two leakage rules shape the inputs. For Task A, every clause containing a percentage is removed from the text and title before training, so that the label cannot be read from the input. The shared `strip_composition` in `src/labels.py` leaves some percentages behind, so `analysis/load_data.py` reapplies a stricter clause filter when it reads the sample; its self-check (`python analysis/load_data.py`) passes, with no digit followed by a percent sign left in any labeled text (the loader's self-check) and 405 labeled listings whose text became empty and are kept (see the data analysis). For Task B, no feature comes from the product's own ratings or reviews; the rating count enters only as a sample weight. Task A is scored by macro-F1, $\frac{1}{K}\sum_k 2P_kR_k/(P_k+R_k)$, so that every material counts equally, and Task B by $\text{RMSE} = \sqrt{\frac{1}{n}\sum_i (y_i - \hat{y}_i)^2}$ and $\text{MAE} = \frac{1}{n}\sum_i \lvert y_i - \hat{y}_i\rvert$ on the unweighted test set. Both are computed through the shared entry point `src/evaluate.py` (`material_scores` and `rating_scores`). Confidence intervals are pending: they will be computed from the saved test-set predictions (`results/material_tfidf_predictions.csv` and `results/rating_predictions.csv`) once the shared bootstrap helper lands in `src/evaluate.py`.

The setup can be reproduced from the public repository with `python analysis/material_tfidf.py` and `python analysis/rating.py`, with scikit-learn 1.9.1, XGBoost 3.4.1, and pandas 3.0.6, and each run writes the command, seed, and data version next to every metric.
