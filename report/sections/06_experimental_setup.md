# Experimental setup

The experiments use the ~250,000-product sample of the Clothing, Shoes and Jewelry metadata file (data version `data/sample.parquet (249,762 rows, make_sample.py 2219c1e)`, seed 42), not the full category of about 7.2 million products. Task A uses the 90,979 listings with a composition string, restricted to the classes with at least 20 labeled listings (`MIN_CLASS_ROWS = 20`; all ten classes of the shared `src/labels.py` pass, so no row is dropped); Task B uses the listings with an average rating and at least 5 ratings (`MIN_RATING_NUMBER = 5`), a filter that drops 30.7% of the rated products (our arithmetic from `data/sample.parquet`). An earlier pilot on the first 10,000 records validated the pipeline; its numbers appear only where labeled as pilot.

Each listing is assigned once to the training set or the test set by `src/make_sample.py`, which hashes the product identifier with seed 42 and sends about 20% of products to the test set; all three tasks use that same assignment. This gives 72,661 training and 18,318 test listings for Task A, and, for Task B, 138,355 training and 34,836 test listings after the filter (199,838 and 49,924 before it). All models are fitted on the training set only, including the TF-IDF vocabulary, the imputation medians, and the one-hot categories, and each model is scored once on the test set. We did not use cross-validation or tune hyperparameters; every setting in the method section was fixed in advance.

Task C adds one streamed pass over the category's review file (`Clothing_Shoes_and_Jewelry.jsonl.gz`, Amazon Reviews 2023), keeping at most the first 20 reviews of each sample product: 866,008 reviews covering 249,705 of the 249,762 products, cached in `data/reviews_sample.parquet` (not committed). The pass yields 209,830 material sentences, and 15,397 products have at least three polar material sentences and so receive a target (12,304 training and 3,093 test products, following the sample's own split). The Task C models use no sample weights, so the sentiment target and the star average can be compared on the same 3,093 test products under the same treatment.

Two leakage rules shape the inputs. For Task A, every clause containing a percentage is removed from the text and title before training, so the label cannot be read from the input; the shared `strip_composition` in `src/labels.py` leaves some percentages behind, so `analysis/load_data.py` reapplies a stricter clause filter when it reads the sample, and its self-check (`python analysis/load_data.py`) passes, with 405 labeled listings whose text became empty and are kept (see the data analysis). For Tasks B and C, no feature comes from the product's own ratings or reviews; the rating count enters Task B only as a row filter and a sample weight, and review text builds the Task C target only. Task A is scored by macro-F1, $\frac{1}{K}\sum_k 2P_kR_k/(P_k+R_k)$, so every material counts equally, and Tasks B and C by $\text{RMSE} = \sqrt{\frac{1}{n}\sum_i (y_i - \hat{y}_i)^2}$ and $\text{MAE} = \frac{1}{n}\sum_i \lvert y_i - \hat{y}_i\rvert$ on the unweighted test set, all through the shared entry point `src/evaluate.py`. Confidence intervals are pending: they will be computed from the saved test-set predictions once the shared bootstrap helper lands in `src/evaluate.py`.

The setup can be reproduced from the public repository with `python analysis/material_tfidf.py`, `python analysis/rating.py`, and `python analysis/review_sentiment.py`, with scikit-learn 1.9.1, XGBoost 3.4.1, and pandas 3.0.6, and each run writes the command, seed, and data version next to every metric (appendix). All runs used the CPU only, on a team member's Windows 11 laptop with 16 GB of RAM; the Task A run took 354 seconds, about 6 minutes (`results/material_tfidf_run.json`), the first Task C pass over the reviews file about 13 minutes (console timing, not recorded in a run file) and its rerun from the cache 486 seconds, about 8 minutes (`results/review_sentiment_run.json`), and the Task B run (`python analysis/rating.py`, with the filter) 1,265 seconds, about 21 minutes (`results/rating_run.json`).
