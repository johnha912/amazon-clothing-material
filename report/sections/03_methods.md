# Methods

Both tasks share one data pipeline and one evaluation discipline. Every experiment trains on the rows marked `split == "train"` and reports on `split == "test"`, with `random_state=42` wherever randomness is involved. Metrics are computed with scikit-learn (`f1_score` with macro averaging for Task A; `root_mean_squared_error` and `mean_absolute_error` for Task B) until the shared evaluation module `src/evaluate.py` lands, and every number in the results files records the command, the seed, and the data version that produced it, so that results from three authors can be merged and re-checked.

For Task A, the input text is the product title, feature bullets, and description with every clause that contains a percentage removed (in either order, such as "90% Polyester" or "Polyester 88%"), because those segments are where the label is parsed from and leaving them in would turn prediction into string matching. Two classical models share an identical TF-IDF representation (word uni- and bigrams, sublinear term-frequency scaling, terms appearing in at least two documents, at most 60,000 features): multinomial-style logistic regression with balanced class weights, and a linear SVM, also with balanced class weights. Classes with fewer than twenty labeled listings in the pilot data are excluded, since they cannot support a train/test split; the merged class list in `src/labels.py` supersedes this cutoff on the full sample. Yanglin's DistilBERT model, described in its own section, uses the same text, split, and metric, and the saved logistic-regression pipeline (`models/material_tfidf.joblib`) doubles as the model behind the demo app.

For Task B, the target is the product's average rating and the allowed inputs are listing fields and the Task A material label. The feature set is deliberately small: log-price, a missing-price indicator, title and text lengths in words, department, and material, with missing materials kept as their own "unknown" category and missing numeric values imputed by the training median. We compare three models of increasing flexibility — predicting the training mean for every product, a random forest of 300 trees, and XGBoost with 400 trees at depth 6 — because the comparison itself answers whether listing fields carry any rating signal at all. Following the team's leakage rules, the number of ratings a product received is never a feature; it enters only as a sample weight (log1p), applied to all three models so that the baseline comparison is fair, so that products whose averages rest on many ratings count more than products rated once, without the model ever seeing the count as an input.
