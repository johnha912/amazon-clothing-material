# Proposed method

For Task A each cleaned listing becomes a TF-IDF vector over word unigrams and bigrams. The weight of term $t$ in listing $d$ is

$$w_{t,d} = \bigl(1 + \log \text{tf}_{t,d}\bigr)\cdot\left(\log\frac{1 + N}{1 + \text{df}_t} + 1\right),$$

where $\text{tf}_{t,d}$ counts $t$ in $d$, $N$ is the number of training listings, and $\text{df}_t$ is how many contain $t$; each vector is then scaled to unit length. The logarithm on term frequency keeps a word repeated ten times from counting ten times as much, and the inverse document frequency lowers words found in nearly every listing ("size", "color") while raising rare, informative ones ("linen", "suede"). We keep terms that appear in at least two listings, up to 60,000 terms, and bigrams let the model see phrases such as "genuine leather" or "cotton blend" as units.

Logistic regression turns this vector $x$ into class probabilities with a softmax, $P(y = k \mid x) = e^{w_k^\top x} / \sum_j e^{w_j^\top x}$, and learns the weights by minimizing $\tfrac{1}{2}\lVert W \rVert^2 + C \sum_i c_{y_i}\bigl(-\log P(y_i \mid x_i)\bigr)$ with $C = 1$. The class weight $c_k = n / (K n_k)$ makes each listing of a rare class count more, so that polyester and cotton do not drown out the other fibers. Each learned weight says how much one word pushes toward one material, which makes the model easy to inspect, and the probabilities give the demo app a natural confidence score. Its drawback is that it treats words independently: it cannot tell "not cotton" from "cotton".

The linear SVM uses the same features but a different goal. For each class it learns a hyperplane that separates that class from the rest (one-vs-rest) with the widest margin, minimizing $\tfrac{1}{2}\lVert w_k \rVert^2 + C\sum_i c_i \max\bigl(0,\, 1 - y_{ik}\, w_k^\top x_i\bigr)^2$, the squared hinge loss, and it predicts the class with the largest score. Listings far on the correct side of the margin cost nothing, so the SVM focuses on hard, borderline listings. Both linear models suit this data because TF-IDF vectors are sparse and very high-dimensional, where classes are often close to linearly separable, and both train in seconds on a CPU, which matters on a catalog of millions of products.

For Task B the inputs are log price, a has-price flag, title and text word counts, and one-hot department and material, with the number of ratings $n_i$ used only as the sample weight $s_i = \log(1 + n_i)$. The baseline predicts the weighted training mean $\bar{y} = \sum_i s_i y_i / \sum_i s_i$ for every product. A regression tree, the building block of both ensembles, splits the data again and again on the feature $j$ and threshold $t$ that most reduce the weighted squared error, $\sum_{i \in L} s_i (y_i - \bar{y}_L)^2 + \sum_{i \in R} s_i (y_i - \bar{y}_R)^2$, and predicts the mean of each final leaf. Trees handle the threshold-like effects we expect (price bands, department differences) and mixed feature types without scaling, but a single deep tree memorizes noise.

The random forest averages 300 such trees, each grown to full depth on a bootstrap sample of the rows, which lowers variance without adding bias. XGBoost instead adds shallow trees one at a time, $\hat{y}_i^{(t)} = \hat{y}_i^{(t-1)} + \eta f_t(x_i)$, each fitted to the remaining error under the objective $\sum_i s_i \bigl(y_i - \hat{y}_i\bigr)^2 + \sum_t \bigl(\gamma T_t + \tfrac{1}{2}\lambda \lVert v_t \rVert^2\bigr)$, where $T_t$ is the number of leaves of tree $t$ and $v_t$ its leaf values ($\gamma = 0$, $\lambda = 1$). We use 400 trees of depth at most 6, learning rate $\eta = 0.06$, and 90% row and column subsampling. The small learning rate and shallow trees mean each step adds only what lowers the loss, which is the property we expect to matter on a target as noisy as average rating. The settings of both tasks are fixed values chosen before seeing test results, not tuned (see the experimental setup).
